Shared Context For All CIRO Feature Plans

Read this before using any atomic plan. It captures repository facts, mobile constraints, backend assumptions, and the non-negotiable delivery rules for future implementation agents.

Current Application Shape

CIRO is a React, TypeScript, Vite, Zustand, MapLibre GL, Recharts, Framer Motion, and Capacitor application. It simulates crisis intelligence and response across Pakistan cities. Existing runtime behavior includes city selection, signal ingestion, crisis activation, map markers, manual dispatch, AI dispatch, route rendering, resource movement, trace logging, replay, compare, what-if, impact panels, and mobile operations dock behavior.

Capacitor And APK Constraints

Every feature must work inside an Android WebView. The Vite base path stays relative. The APK must not contain private API keys. Network calls from the APK must target a hosted HTTPS backend or fall back to bundled data. Touch interactions must not rely on hover, right-click, desktop keyboard shortcuts, or wide-screen-only panels.

Backend And Key Custody

OpenRouter, traffic, map, weather, and other live data provider keys live in backend environment variables. Frontend settings can expose provider status, selected models, and feature toggles, but never raw secrets. Preferred backend target is Cloud Run, with any equivalent HTTPS host acceptable for demo continuity.

Atomic Commit Rules

Every future implementation must inspect git status first, preserve unrelated changes, stage only files owned by the atomic task, run fresh verification, and commit with a narrow message. Planning artifacts may be committed separately from runtime app changes.
